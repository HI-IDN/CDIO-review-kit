# Evidence Model

CDIO Review Kit treats engineering assessment as evidence gathered throughout
the development process rather than assessment of the final artifact alone.

## Artifact evidence

Examples:

- report;
- code;
- calculations;
- figures;
- datasets;
- tests;
- final outputs.

## Process evidence

Examples:

- commits;
- issues;
- pull requests;
- reviews;
- discussions;
- project boards;
- revisions.

## Understanding evidence

Examples:

- explanations;
- justification of decisions;
- validation;
- identification of assumptions;
- response to feedback;
- ability to modify existing work.

## Oral evidence

The instructor's team assessment can reveal understanding that is not observable
through GitHub.

It can also test hypotheses raised by repository evidence.

## Triangulation

No single evidence source should automatically determine contribution or
understanding.

For example:

Low commit count
→ investigate other evidence
→ examine issues/reviews/roles
→ ask student if necessary
→ instructor judgment.

The purpose of analytics is to direct instructor attention, not replace it.
