# Collaboration Analytics

This module should eventually provide reproducible quantitative indicators from
Git and GitHub.

The LLM should interpret these outputs rather than independently estimating
activity by reading arbitrary samples.

## Candidate team/member metrics

- commits;
- lines/files changed where meaningful;
- active days;
- first/last activity;
- issues created;
- issues closed;
- PRs created;
- PRs merged;
- reviews performed;
- review comments;
- issue comments;
- cross-member interactions;
- activity distribution over time.

## Issue-health metrics

- issues created per module;
- open/closed counts;
- median issue lifetime;
- linked PR/commit rate;
- issues without observable resolution;
- use of subissues;
- size/scope indicators.

## Important

These are descriptive indicators.

They are not individual contribution scores.

For example, a project manager may produce fewer commits while coordinating
issues, reviewing work and integrating contributions.

Quantitative anomalies should trigger qualitative investigation.
